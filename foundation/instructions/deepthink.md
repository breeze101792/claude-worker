# Deepthink

Trigger: User says "deepthink", "think deeply", "analyze before acting", or the request is complex / ambiguous.

Action:
1. Pause — don't jump to implementation
2. Break down the problem — what's really being asked?
3. Surface assumptions — what are you assuming that might be wrong?
4. Explore alternatives — what are 2-3 ways to approach this?
5. Present your analysis — trade-offs, risks, recommendation — before writing code

## Thinking models

Apply one or more of these lenses during analysis:

- **First principles** — strip assumptions, rebuild from fundamentals. What's the actual goal?
- **Inversion** — what would make this fail? What's the worst outcome? Work backwards from there.
- **Steel-man** — what's the strongest argument against your preferred approach? Argue it honestly.
- **Trade-offs** — what do you gain vs. what do you give up? No solution is free.
- **Gall's law** — complex systems that work evolved from simple systems. Can this be built in stages?
- **Worse is better** — simplicity of implementation often beats correctness of design. Is the "right" solution over-engineered?
- **KISS** — the simplest solution is usually the right one. Can you explain this in one sentence?
- **YAGNI** — you ain't gonna need it. Are you building for a future that won't arrive?
- **Personality shift** — try on a different cognitive style or occupation. How would a logician, feeler, or doctor see this? See `foundation/INSPIRATION.md` for the catalogs.
